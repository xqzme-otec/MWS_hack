# CompactFactExtraction — формат данных и схема фактов

Корпус: русскоязычные транскрипты звонков в техническую поддержку (клиент — оператор)
с эталонной разметкой фактов. Транскрипты синтетические, с имитацией ошибок ASR
(порча слов, пропуски, обрывы реплик) и разговорными дизфлюенциями.

## 1. Формат диалога

Каждая строка JSONL — один звонок:

```jsonc
{
  "call_id": "u101_00042:call0001",        // уникальный идентификатор
  "started_at": "2026-05-11T09:00:00",     // метаданные: дата/время начала — якорь
                                           // для нормализации относительных дат
  "duration_sec": 412,
  "series": {                               // связь звонков одной истории (или null)
    "account_id": "u101_00042",             // аккаунт клиента
    "call_index": 1,                        // порядковый номер в серии
    "series_len": 3                         // всего звонков в серии
  },
  "turns": [
    {"idx": 0, "speaker": "operator", "text": "…"},
    {"idx": 1, "speaker": "client",  "text": "…"}   // текст УЖЕ с ASR-шумом
  ],
  "noise_level": 0.25,                      // уровень шума этого звонка
  "facts": [ /* эталонные факты, см. §2; в predictions факты — ваш вывод */ ]
}
```

## 2. Схема факта

```jsonc
{
  "object": {"id": "u101_00042:svc0",       // идентификатор объекта (уникален в аккаунте)
             "type": "service",             // service | device | ticket | client
             "name": "домашний интернет"},  // упоминание в тексте может отличаться
  "attribute": "service_state",             // атрибут, см. §3
  "value": "периодические обрывы",          // значение (нормализуйте к каталогу!)
  "polarity": 1,                            // 1 утверждение | -1 явное отрицание клиентом
  "speaker": "client",                      // говорящий реплики-источника
  "valid_from": "2026-05-06T00:00:00",      // абсолютная дата, нормализованная
  "valid_to": null,                         // null = действует дальше; иначе закрыт
  "source": {"turn_idx": 7,                 // реплика-носитель
             "span": [14, 47],              // символьные оффсеты в turns[i].text (или null)
             "quote": "интернет со вторника пропадает"}  // дословная цитата (или null)
}
```

Даты в тексте звучат ОТНОСИТЕЛЬНО («со вторника», «вчера», «через неделю», «после двух»)
— нормализуйте их относительно `started_at` звонка. Эталонные `valid_from/valid_to` —
ISO-даты; время суток присутствует только когда оно явно озвучено.

## 3. Онтология

| attribute | смысл | одно-значный? | примеры значений (по каталогу) |
|---|---|---|---|
| `service_state` | состояние услуги/устройства | да (вытеснение) | работает нормально; периодические обрывы; красный индикатор; двойное списание |
| `tariff` | тарифный план клиента | да (переход) | «Базовый», «Анлим+», «Мой онлайн» |
| `ticket_status` | статус заявки | да (цепочка) | принята → в работе → назначен выезд специалиста → выполнена |
| `action` | выполненное клиентом действие | нет | перезагрузка роутера — не помогло |
| `agreement` | договорённость (срок = valid_from) | нет | выезд специалиста; возврат средств |

Каталог нормализации значений — `catalog.json` (услуги/тарифы/устройства/симптомы/
действия/статусы). Разговорные варианты («инет», «телек», «приставка») сопоставляйте
с каталогом — это заявленная сложность кейса.

## 4. Ловушки (не факты!)

- предложение оператора, НЕ подтверждённое клиентом («можем предложить…» — нет «да»);
- догадка оператора, отвергнутая клиентом («У вас тариф „Базовый“?» — «Да нет, „Плюс“»);
- упоминания посторонних людей, технических деталей и тем не по адресу;
- гипотезы, вопросы, цитаты из чужих слов без подтверждения.

## 5. Метрики (`case_metrics.py gold.jsonl pred.jsonl`)

- `fact_precision / fact_recall` — совпадение по объекту (fuzzy) + атрибуту + значению
  (fuzzy ≥0.85) + полярности;
- `temporal_recall` — среди сопоставленных: верные даты начала/конца (по дню);
- `state_accuracy` — актуальное значение одно-значных атрибутов после всех изменений;
- `grounding_turn / grounding_span` — верная реплика-источник; пересечение спанов.

Формат `pred.jsonl` — тот же формат звонка; в `facts` достаточно полей `object.name`,
`attribute`, `value`, `polarity`, `valid_from`, `valid_to`, `source.turn_idx`
(span/quote — по желанию, но повышают grounding).
